# ubot_worlds

These are the Gazebo Harmonic worlds for the ubot benchmark. Each world renders from
`worlds/<world>.sdf.xacro` with `condition:=nominal|glass|dynamic|degraded|low_light` and
`physics:=dartsim|bullet-featherstone`.

| World | Source | Notes |
|---|---|---|
| `arena_5x5` | This package | Replica of the physical arena; the file is the arena build spec |
| `small_house` | AWS RoboMaker small house (Harmonic port) | Rooms, doorways, furniture |
| `bookstore` | AWS RoboMaker bookstore (Harmonic port) | Aisles; storefront windows above a sill |
| `small_warehouse` | AWS RoboMaker small warehouse (Harmonic port) | Open space beyond 12 m sensor range |

- **Models.** The ~140 MB of AWS models are not committed. `scripts/fetch_models.sh` downloads
  them at a pinned commit of github.com/zp78-ship-it/turtlebot-maze (`tb_worlds/models`, MIT;
  the AWS assets were originally MIT-0) into `models_external/`. The build installs them, and an
  environment hook adds them to `GZ_SIM_RESOURCE_PATH`.
- **Generated files.** The AWS world files are generated by `scripts/import_aws_world.py`, which
  forces furniture static and makes the ceiling lights switchable.
- **Condition geometry.** Glass panes and walkers are defined in `missions/<world>.yaml`, the same
  file that holds the spawn pose, bounds, goals and mapping route (`ubot_bench make_missions`).
- **Ground-truth maps.** `maps_gt/` holds the scan-plane and traversability maps built by
  `ubot_bench gt_map`.

```bash
ros2 launch ubot_worlds gz_world.launch.py world:=small_house condition:=glass
ros2 launch ubot_bringup sim.launch.py world:=bookstore sensor_profile:=lidar_ld06
```
